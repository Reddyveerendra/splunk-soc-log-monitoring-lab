# Configure rsyslog for Log Collection

## Overview

In this step, we configure **rsyslog** on the Ubuntu server to collect and store system logs in a dedicated file. These logs will later be monitored and analyzed using Splunk as part of the SOC lab environment.

`rsyslog` is the default logging service in Ubuntu and is responsible for collecting system logs generated by various services such as SSH, authentication services, and system processes.

---

## What is rsyslog?

**rsyslog** is a powerful logging service used in Linux systems to collect, process, and store log messages from different sources.

Key capabilities of rsyslog:

- Collects system and application logs
- Supports centralized log management
- Filters and routes logs to different files
- Works with SIEM platforms like Splunk

---

# rsyslog Configuration Steps

## Step 1: Verify rsyslog Service

First, check if the rsyslog service is running.


sudo systemctl status rsyslog

Expected output should show the service as active (running).

## Step 2: Create a Directory for Custom Logs

Create a directory to store the SSH logs that will be monitored by Splunk.

sudo mkdir -p /var/log/websrv-02

Verify the directory:

ls /var/log/
## Step 3: Configure rsyslog to Capture SSH Logs

Edit the rsyslog configuration file.

sudo nano /etc/rsyslog.d/sshd.conf

Add the following configuration:

if $programname == 'sshd' then /var/log/websrv-02/sshd.log
& stop

This configuration tells rsyslog to capture all SSH-related logs and store them in a separate log file.

## Step 4: Restart rsyslog Service

Restart the rsyslog service to apply the new configuration.

sudo systemctl restart rsyslog

## Step 5: Generate SSH Logs

To generate logs, attempt an SSH login to the server.

Example:

ssh username@localhost

You can also attempt failed login attempts to generate authentication logs.

## Step 6: Verify Log Collection

Check whether the logs are being written to the new log file.

sudo cat /var/log/websrv-02/sshd.log
